# Описание проекта

## Структуры данных и алгоритмы

### Состояние игры

Секретное число хранится в строке. Так удобно сравнивать цифры по их позициям.
Кроме обычных цифр, строка позволяет хранить буквы из шестнадцатеричной системы
счисления.

История попыток хранится в массиве "guessHistory". Каждый элемент массива — это
объект "GuessHistoryEntry". В нём находятся введённое число, количество быков и
количество коров.

Лучшие результаты хранятся в массиве "gameRecords". Каждый объект "GameRecord"
содержит количество попыток, время игры, длину числа и систему счисления.

Новые попытки и результаты добавляются через оператор spread. В результате
создаётся новый массив, а старый массив не изменяется.

Для сохранения уже рассчитанного количества возможных чисел используется
"Map". Ключ состоит из длины числа и системы счисления, а значение хранит
результат подсчёта.

### Функция "evaluateGuess"

Сначала секретное число и попытка игрока переводятся в нижний регистр. Это нужно
для правильного сравнения букв шестнадцатеричной системы.

Затем каждая цифра секретного числа проверяется два раза:

1. Если такая же цифра стоит на той же позиции, это бык.
2. Если цифра есть в попытке, но стоит на другой позиции, это корова.

Функция возвращает объект с количеством быков и коров.

### Функция "countPossibleSecrets"

Функция считает, сколько разных секретных чисел можно создать для выбранной
длины и системы счисления. Цифры в числе не должны повторяться.

Для подсчёта используется рекурсия. После выбора первой цифры для следующей
позиции остаётся на одну цифру меньше:

"base * (base - 1) * (base - 2) * ..."

Когда длина становится равна нулю, функция возвращает "1", и рекурсия
заканчивается. Готовый результат сохраняется в "Map". Если такой подсчёт уже
выполнялся, функция берёт сохранённое значение.

## Сложность алгоритмов

В описании ниже "n" — это длина секретного числа или попытки игрока.

### Функция "generateSecret"

Средняя временная сложность — O(n²). Функция добавляет цифры по одной и перед
добавлением проверяет методом "includes", нет ли такой цифры в строке. Чем
длиннее строка, тем больше символов нужно проверить. Случайное число иногда
может повторяться, поэтому цикл может выполнить дополнительные итерации.

### Функция "evaluateGuess"

Временная сложность — O(n²). Первый "filter" проверяет позиции цифр. Во втором
"filter" для каждой цифры вызывается "includes", который просматривает попытку
игрока. Получается, что для каждой цифры может быть просмотрена вся строка.

### Функция "isValidGuess"

Временная сложность — O(n). Функция проверяет длину строки, допустимость каждой
цифры и отсутствие повторов через "Set". Каждая цифра обрабатывается несколько
раз, но количество таких проходов не зависит от длины строки.

### Функция "countPossibleSecrets"

При первом вызове временная сложность — O(n). На каждом шаге рекурсии длина
уменьшается на один, пока не станет равна нулю. Результаты сохраняются в "Map".
Повторный вызов с теми же значениями берёт готовый результат из "Map", поэтому
его сложность — O(1).

## Принципы чистого кода

### Понятные имена

Имена функций говорят, что они делают. Например, функция "generateSecret"
создаёт секретное число, "isValidGuess" проверяет попытку игрока, а
"countPossibleSecrets" считает количество возможных секретных чисел.

### Одна задача у функции

Функции игровой логики разделены по назначению. Файл
"src/game/generate-secret.ts" отвечает за создание секрета, а файл
"src/game/evaluate-guess.ts" отвечает за подсчёт быков и коров. Эти функции не
создают элементы страницы и не меняют интерфейс.

### DRY

Проверка допустимых цифр не написана два раза. Функция
"createDigitValidator" используется в "isValidGuess" для проверки готовой
попытки и в "handleGuessInput" для фильтрации символов во время ввода.

### KISS и YAGNI

Игровая логика написана обычными функциями без классов и дополнительных
библиотек. В проекте нет сервера и внешнего API, потому что для выполнения
задания они не нужны.
